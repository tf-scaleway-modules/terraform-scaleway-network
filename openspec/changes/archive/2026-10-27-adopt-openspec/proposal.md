# Proposal

## Why

This module has never used a spec system: no Agent OS, no OpenSpec. Its contract lives only in `variables.tf`, `main.tf` and `outputs.tf`. Adopting OpenSpec (the same flow as the sibling `keycloak` and `vault` modules) gives the module a written baseline contract that later changes can modify with delta specs, and routes contributors and coding agents to the pinned engineering-standards stores.

## What Changes

- Configure `openspec/config.yaml` (pinned `quality`, `repository`, `terraform` stores, module context, per-artifact rules, operations guidance) and add `AGENTS.md` and `CLAUDE.md`.
- Install the `openspec-*` skills for Claude Code (`.claude/skills/`) and OpenCode (`.opencode/skills/`).
- Tooling: pin node and the `openspec` CLI in `mise.toml`, add `spec-validate` and `spec-setup` tasks, add `scripts/openspec-setup.sh`, validate specs in CI through `.gitlab/specs.yml` (`validate:specs`, `OPENSPEC_VERSION` in `.gitlab/global.yml`).
- Write baseline capability specs under `openspec/specs/`, describing the module as released today.
- README "Contributing" section points to the OpenSpec workflow.
- No change to any `.tf` file, input, output or resource: semver **patch**, nothing lands in state differently, no consumer impact. CHANGELOG.md stays generated by git-cliff.

## Capabilities

### New Capabilities
- `module-contract`: OpenTofu/Terraform and provider constraints, no provider/backend blocks, project lookup, input and output surface.
- `vpc`: the VPC, its routing flags, region, zones validation and tags.
- `private-networks`: private networks keyed by name with optional names, subnets and tags, and the network outputs.
- `public-gateways`: per-zone gateways, flexible IPs, bastion, SMTP, masquerade, IPAM IPs, gateway-network attachments and their outputs.
- `access-control-list`: the optional VPC access control list.
