# Design

## Context

- First adoption: the repository had no earlier planning system and no `tests/` directory.
- The `keycloak` and `vault` modules already use OpenSpec with the same stores, `AGENTS.md` / `CLAUDE.md` shape, setup script and CI job.
- CHANGELOG.md is generated by git-cliff (`.cliff.toml`, `mise run changelog`) from commit subjects.

## Goals / Non-Goals

**Goals:**
- One planning system (OpenSpec) with standards consumed by pinned reference, never copied.
- A baseline of the current contract that later changes modify with deltas.
- Zero diff in `.tf` files, so this change cannot break a consumer.

**Non-Goals:**
- Applying the store standards to the code (unit tests, validations, checks).
- Correcting inconsistencies noticed while writing the baseline.

## Decisions

### 1. Stores pinned through the terraform-module profile
`openspec/config.yaml` references `quality`, `repository` and `terraform` at the tags of the profile. Alternative: copy the standards into the repo; rejected, they would drift.

### 2. Skills for Claude Code and OpenCode
The same `openspec-*` skills are installed in `.claude/skills/` and `.opencode/skills/`; OpenCode reads `AGENTS.md` natively and `CLAUDE.md` imports it.

### 3. CI job `validate:specs`
`.gitlab/specs.yml` runs `openspec validate --all --strict` at the version of `OPENSPEC_VERSION`, equal to the mise pin. Stores are a developer-machine concern only.

### 4. Capability split by Scaleway object
`module-contract` plus `vpc`, `private-networks`, `public-gateways`, `access-control-list`. The gateway, its flexible IP, bastion, IPAM IPs and gateway-network attachments share one capability because they are created together from the same zone set. No `check` blocks exist, so there is no guardrails capability.

### 5. Baseline describes today's behaviour
Specs state what the code does, including quirks (for example, a reserved flexible IP wins over an existing IP id). Quirks that are unclear are left out and reported.

### 6. CHANGELOG stays generated by git-cliff
`AGENTS.md` and `config.yaml` ask for commit subjects that read as CHANGELOG lines and for `mise run changelog` at release, not a hand-edited Unreleased section.

## Risks / Trade-offs

- [Baseline misstates behaviour] -> Every scenario is derived from `variables.tf`, `main.tf`, `locals.tf` or `outputs.tf`; no tests exist to cross-check, so the first change adds `tests/main.tftest.hcl`.
- [Contributors without stores get no standards] -> `mise run spec-setup`; `AGENTS.md` says to stop rather than guess.

## Migration Plan

1. Merge to `develop`; no tag required, patch at the next release.
2. Each contributor runs `mise install` then `mise run spec-setup` once.

Rollback: revert the merge; no state or consumer is affected.
